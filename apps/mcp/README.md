# mcp

`mcp` is the hosted Model Context Protocol facade for Duet. It exposes agent-safe
tools over HTTP, authenticates with the caller's Duet bearer token, checks
workspace capabilities, and forwards the actual work to the REST API or model
gateway.

## Boundary

This app owns MCP transport and tool adaptation, not a second copy of Duet's
business logic. If a tool maps to an existing REST operation, the REST API remains
the source of truth. If a tool describes shared input grammar or capability
requirements, that shape belongs in [`@repo/contract`](../../packages/contract/README.md).

The Streamable HTTP resource is served only at the origin root. `/mcp` is a
deleted path, not a redirect or compatibility alias. An unauthenticated root
request returns a Bearer challenge pointing to RFC 9728 protected-resource
metadata (PRM); that metadata points clients to the API-owned authorization
server.

OAuth access is bound to the canonical MCP origin. MCP asks `ctl` for the
credential kind and audience, rejects an OAuth bearer for any other resource,
then adapts accepted calls onto REST or gateway operations. Ordinary
first-party Duet keys remain pasteable. The rationale—and the explicit
token-passthrough tension created by forwarding one bearer inside the
first-party trust domain—lives in the canonical
[security model](../../SECURITY.md#oauth-credentials-resource-bound-expiring-grant-families).

## Pointers

- `src/http.ts` owns the public resource-server boundary: Streamable HTTP,
  PRM discovery, root-only routing, and authentication. `src/server.ts` owns the tool registry,
  capability declarations, REST forwarding, and media generation bridge.
- `src/file-resources.ts` validates API-created file references and performs the
  single MCP adaptation from `FileResource` to `ResourceLink`. It also validates
  direct upload sessions. Tools consume those shared transfer seams instead of
  constructing VM URLs or file metadata themselves.
- Model discovery describes upstream capabilities; it never decides whether a
  model ID is allowed. `src/tools/media.ts` keeps role defaults separate from exact
  upstream IDs and shares SDK operation selection with the CLI runtime. Missing
  capability metadata leaves an explicit native image request usable.
- `generate_media` creates an ordinary durable Drive file under
  `mcp/generated-media/`, uploads its bytes directly to the workspace VM, and
  returns the same one-link result as a binary `read_file`. It does not return a
  second base64 or structured copy of the generated bytes.
- MCP input schemas live with the shared contract in `packages/contract/src/mcp`.
- Standalone function packaging retains the AI SDK’s dynamically loaded Node
  downloader; a manifest dependency alone does not make it part of the bundled
  deployment. `scripts/vercel-bundle.mjs` owns that artifact.
- Deployment details live in the root
  [Deployment (Vercel)](../../README.md#deployment-vercel) section.

Run `bun run probe:file-resources` to exercise generated image and video results
through the official MCP SDK client with a local fake transport. The probe
asserts discovery → model → API upload session → raw VM upload → API file-reference
sequence and prints the discovered metadata and final ResourceLinks.
