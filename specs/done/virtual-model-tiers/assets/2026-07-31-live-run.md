## What passes, live

Legs 1–4, every time they were reached:

- **Versions** — the workspace reports an agent and gateway version. NOTE: the
  leg only asserts they are PRESENT; it does not pin a value, so the handoff's
  "must report 0.3.7" describes prose, not the assertion. Staging's active
  workspaces all report **0.3.8**.
- **Subscriber default** — `defaultTier.access === 'all_tiers'`; an explicit
  Standard default is set and read back.
- **Routed session** — a Standard session completes and produces a
  `gatewayGenerations` row with `tier: 'balanced'` and a model inside balanced's
  closure. This is the live proof that `x-duet-tier` survives agent → gateway →
  backend.
- **Billing math** — the journey's independent recompute of
  tokens × Standard rates equals the ledger debit exactly, and
  `upstreamCostMicroUsd` is present and different. The hardest leg, and it holds.

## What fails, and where the break is

Leg 5: after `POST /messages` with `tier: 'frontier'` on a live session, the next
tiered generation is still attributed `balanced`.

Both hops inside this repository are correct, and are pinned by tests that pass:

1. **API** — `resolveSessionTier` prefers `requested` over `sessionLast`
   (`packages/backend/convex/domains/agentSessions/delivery.ts`), and
   `apps/api/src/index.test.ts` asserts the follow-up gateway call carries
   `launch.tier` = the newly requested tier.
2. **Gateway** — `durablePromptCommand`
   (`packages/gateway/src/agent-sessions/coordinator.ts`) puts
   `tier: args.launch.tier` on the prompt command sent over RPC to an
   ALREADY-RUNNING runner; it is not only a spawn argument.

**Where the break is: NOT ESTABLISHED.** The two hops above are covered by unit
tests that use a fake gateway and a fake runner, so they prove the wiring, not
the live path. The obvious next suspects, in order:

1. Whether the follow-up took the live-runner branch at all. `deliver()` sends
   the tier per-prompt only when the existing runner `isAlive()`; the relaunch
   branch passes `args.launch.tier` (correct), but the WAKE and
   `recoverCommands` paths launch from `envelope.launch.tier` — the LEDGER's
   stored launch, not the new request's. If a settled session goes through one
   of those, a stale tier is exactly what you would see.
2. Whether the agent applies a per-prompt tier at all on 0.3.8.

Distinguishing them needs the VM's gateway log around the follow-up (which
branch ran) plus the launch record in the session ledger. That is one focused
run away and was not done here.

## Correction

An earlier version of this note asserted the break was in `duet-agent` 0.3.7 and
needed an agent release. Both halves were wrong: the fleet runs 0.3.8, and no
evidence collected here locates the break on either side of the RPC boundary.

## Reproducing

The failure is deterministic once leg 5 is reached. The two earlier failures are
load flakes in real-model turns and are unrelated to tiers — re-run until leg 5
is reached.
