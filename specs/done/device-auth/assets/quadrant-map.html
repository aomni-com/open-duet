Phase 2 — MCP OAuth

HI Expiry enters the hot auth path sharp edge

No credential in apiKeys expires today — whoami/key authorization has no expiresAt check. The oauth kind adds one to the path every product request flows through; must be cheap and must not regress user/sync_device/app kinds.

HI Refresh rotation self-nuke on client retries decided (ledger #17)

A network-flake retry of the same refresh token must not trip reuse-detection and revoke the grant family. Idempotent same-token handling within a short window; genuinely old tokens still kill the family per OAuth 2.1.

MD CIMD is SSRF by design sharp edge

The AS fetches an attacker-supplied client_id URL. Application-level guard (private-IP/redirect blocking) — network-level controls don't exist inside Vercel functions. Spec's security section is the checklist.

MD The MCP app doesn't know its own name small fact OPEN

PRM + audience validation need a canonical self-URL; apps/mcp/src/config.ts only knows api + gateway. New DUET_MCP_PUBLIC_URL via the secret-topology rail, both envs. OPEN: confirm the MCP deploy domain with Example User at build time.

LO Residuals noted

401 shape change (adding WWW-Authenticate) is additive-safe. New tables: oauth clients (DCR) + CIMD cache + grants/refresh tokens. Rate-limit rail extends to token/register endpoints. Consent-component factoring from phase 1 is a refactor-clean checkpoint, not a copy-paste.

  1. Approval/consent card layout details — picker order, role display, client-identity header placement (phase 2). Tweak freely.

  4. Eligibility semantics — role grants every requested capability (all-or-nothing); partial grants rejected as scope creep.

  1. Auth stack: oauth kind with expiresAt + audience; expiry check in key authorization.
