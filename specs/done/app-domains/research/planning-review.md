# Planning synthesis and fog audit

Three independent drafts reconnoitered the same brief without seeing one another’s
plans. A fewest-slices draft proposed four coherent rungs; a seam-quality draft
proposed nine; risk-first proposed early hosted/auth proof and separate address
projection. The risk-first consultation used Claude Opus/high through the Claude
skill, with read-only tools. Claude could inspect Duet but was denied legacy-repo
reads; those reference claims were verified separately by the parent/drafter.
No runtime tests or production edits were delegated.

## Chosen cuts and rejected alternatives

| Decision | Reason / rejected alternative |
| --- | --- |
| Eight slices, with provider, lifecycle and serving separate | They have different failure oracles. The four-rung plan bundled external parity/database effects and broad UI/live completion. The nine-rung plan’s separate metadata/API rungs were reunited into one useful management contract. |
| Existing canonicalUrl becomes the primary standalone URL | Adding primaryUrl beside canonicalUrl would ask every consumer which is the real address. One shared selector updates API and public gateway prompt; embedding already has a separate launch owner. |
| Keep standard launch for every iframe | Initially only private framing was highlighted. The user clarified this is required for public apps too, to remove custom DNS as an embedded dependency. All contracts/slices adopt that broader rule. |
| One existing edge project, staging branch explicit | Live account inspection settles topology; a separate edge project would invent unnecessary infrastructure. |
| User-authorized aomni.co apex | Its accepted existing DNS removes the guessed DNS-zone/token prerequisite. The old assignment was freed; no DNS/registrar edits were needed. |
| Domain-owned cleanup, no generic queue | Legacy swallowed provider deletion failure; retaining a small removal reservation changes a real routing/reuse outcome. Existing Convex scheduler remains the work mechanism. |
| Uniform local binding management for owners/editors | Domains are local addressing metadata, not origin runtime edits or publication. Do not reuse source-file edit controls or add key-kind carve-outs. |
| Conditional existing-rail private return | A small protected handoff can reuse sign-in and grants. Prove it independently; the user’s 403 fallback is valid if it requires broad auth redesign. |

Rejected additions from the consultation: a separate ownership-TXT security tier,
new DNS-provider integration, unrelated hostname-provider bans, separate identity
credentials, generalized CSP-policy changes, and broad provider-orphan sweeping.
They are outside the requested port or not required by the observed target.

The assumption that every deletion already uses `deleteAppRow` was rejected after
reading `apps/replication.ts:deleteReplica` and the workspace deletion owner.
Slice 03 explicitly covers those bypasses without changing their unrelated policy.

## Refactor-clean and scrollback audit

The materialized plan assigns one owner to domain lifecycle, provider observation,
app admission, primary URL selection, embedded launch, indexing headers, management
UI, and environment identity. Existing contract/provider scaffolding is replaced,
not wrapped; production fakes and transition compatibility layers are not planned.
Public gateway prompt URLs and all app deletion consumers were included after
checking their actual owners. No unrelated gateway/renderer refactor is needed.

Independent post-materialization reviews caught four gaps and the plan was repaired:
orphan cleanup now has an internal retry-by-ID surface, public collection/controls/
refusal shapes are explicit, delayed attach effects must settle before cleanup can
release reservation, and remote target validation applies beyond add replay.
The optional auth fallback now removes its own scaffolding; positive feasibility
freezes the launch-query contract. Address-only gateway metadata retains the
existing no-restart behavior.

All user decisions are in the README ledger: app-only scope, one-domain simplification,
dual management entry, exact settings label, primary standalone URL with working
Duet alias, conditional general private sign-in, public custom indexing, no migration,
full aomni.co authorization, and every-embedded-standard-host clarification.
The preserved exploration map is marked superseded for build instructions; the
historical integration note points here rather than claiming current shipped code.
The spec remains planning-only. No staged/live implementation success is implied.
