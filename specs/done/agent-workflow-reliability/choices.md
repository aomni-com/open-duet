# Implementation choices

These decisions describe the final 0.3.30 release and its verification harness. Explicit user directions—preset advisors off, a hard cutover, Balanced on Sonnet 5.5 and Economy retained on current DeepSeek—are distinguished from implementation choices below.

## Recovery and scope

- **Warn rather than prohibit repeated work.** The user did not prescribe retry policy. Three retained identical settled attempts trigger recovery guidance, but a retry remains possible because an external dependency may have changed. Missing history cannot establish sameness. A hard ban would turn useful retries into a product restriction.
- **Keep report accuracy as guidance and evaluation.** Claims must distinguish observed results, hypotheses and uncertainty. A separate evaluator checks reports against evidence; the runtime does not impose a universal semantic approval gate on customer releases. This leaves residual model-reporting risk, explicitly recorded in the outcome results.
- **Do not add a new orchestration policy in this release.** Investigation showed the agent introduced Example User's original relays. That is evidence for a future direct-execution comparison, not proof of its outcome. The shipped change repairs existing relay contracts without another untested change to when agents choose relays.
- **Retain bounded receipts, not a second full prompt archive.** Previews and fingerprints support execution diagnosis and unchanged-work detection. Complete instruction retention added storage/projection rules without preventing drift, so the optional experiment was removed. Its results remain historical evidence, not a current runtime requirement.

## Tool and persistence boundaries

- **Validate once at the shared admission boundary.** Original arguments pass through any intentional tool-owned preparation, then validation precedes generic SDK coercion and handler effects. This retains supported edit-tool forms while rejecting malformed controls. Fixed owned envelopes are closed; declared open data maps remain open. Bounded path errors avoid echoing values, and lazy cached schema compilation avoids unnecessary startup work.
- **Keep the existing nested relay grammar.** Re-teach and enforce one schema instead of introducing flat aliases or a migration parser. A parent pass accepts one control decision and applies it before remaining messages, preserving explicit sequencing. A minimal terminal selection remains an escape from invalid state input or directories; invalid initial states cannot replace active work.
- **Use constructed execution as the source of evidence.** Existing decision history receives a receipt only after executor preparation, with actual start recorded separately. Directory, rendered instructions and inherited context determine identity; unused input cannot make unchanged work look different. No parallel receipt service or intent interpretation layer is introduced.
- **Deliver corrections through existing state and input owners.** Definition edits or persistent overrides change future work; normal relay control retains pending messages until consumption, and edited follow-ups replace pending copies across restore. Explicit interruption retains its existing queue-clearing behavior; it does not guarantee delivery of an unconsumed correction. Templates and explicit inherited context carry data without silently appending every user message to every worker. This preserves scoped workers without a second correction database.

## Model policy

- **Disable advisors in shipped presets, retain custom opt-in.** The user requested the preset policy change. Existing advisor machinery and historical messages remain so separately authored configurations keep their explicit choice. Current managed policy applies on resume and nested launches; running processes drain normally rather than being killed for the update.
- **Advance Sonnet without rewriting explicit historical selections or tariffs.** Balanced's requested routes use Sonnet 5.5 while its specialized visual route stays intact. Existing registry and gateway contracts supply support. Explicit older Sonnet selections keep their meaning, and customer tariff policy remains independent of upstream model changes.
- **Retain Economy's current target and documented limitations.** The user accepted its failed report-accuracy outcomes and requested latest DeepSeek. The alias already selects V4.1 Flash, so no extra model experiment or routing change ships. Acceptance does not convert failed outcomes into passes.

## Verification design

- **Separate behavior proof from report judgments.** Synthetic outcomes use deterministic probes, while an explicitly selected evaluator judges report accuracy. Worker reports show what was said, not proof that claimed checks ran. Staging uses independent browser/provider/release evidence without buying a duplicate report judgment. A truthful report of an unavailable provider can pass its outage scenario without pretending the task succeeded.
- **Share one fixture and oracle across execution environments.** The published agent archive owns task definitions; local and staging harnesses supply transport and resource collection. Expected results and provider integrity remain independent of editable task code. This is experiment integrity, not a new workspace security boundary. Disposable resources use the existing verified-cleanup ledger.
- **Keep experiments controlled and preserve failures.** Warning recovery uses a forced three-attempt setup and establishes a bounded continuation capability, not an improvement rate. The missing-fallback eval fixes an explicit text-only route, leaving classifier-driven fallback to its separate test. Provider fixtures must actually support their advertised success queries. Container-local databases avoid host-filesystem distortion. Original failures remain when a fixture or environment is corrected.
- **Keep actor and evaluator attempts distinct.** Exact saved reports may be rejudged when source/input/event identities match, but that cannot replace missing task evidence or reset actor budgets. No silent model/provider fallback occurs when judgment is unavailable. The user's explicit replacement-attempt allowance is preserved separately in historical evidence.
- **Concentrate deployed verification on two Balanced journeys.** Both assert actual advertised Sonnet execution, installed release identity and advisor-off policy. The broader tier matrix belongs to local live evals. Preflight covers the normal rollout slot, control-plane poll and install allowance before starting the separate task budget; short fixture names fit real DNS labels. This avoids multiplying paid task runs while retaining the deployed boundaries under test.
