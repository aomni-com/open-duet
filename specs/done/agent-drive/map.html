DUET · AGENT DRIVE · QUADRANT MAP · 2026-07-06

Agent Drive — the completed map

Duet v2: the shared drive any agent works in. Rebuilt from scratch in ~/dev/duet, API-first, on exe.dev VMs. This map is the deliverable of the unknowns walk — every decision, sharp edge, and open item lives here, not in chat scrollback.

Quadrant 1 · Known knownsThe settled ground

The thesis (extracted in Stage 3, governs everything)

Ride the existing agent ecosystem; don't compete with it. Claude Code / Codex / OpenClaw are subsidized and familiar — v1 failed by demanding users learn a new webapp and a new harness. v2's spine is CLI + MCP + memory for the agents users already run. Duet's own harness and web app are second-order layers on the same API.

Product decisions

  • Workspace = first-class resource = one exe.dev VM; its disk is the drive and the source of truth. Users create many; full membership (owner / editor / viewer) at launch; no "personal vs team" type — first workspace is just auto-created.
  • Files API: variant A, path-as-URL (GET/PUT /v1/ws/{ws}/files/{path}).
  • Memories: separate routes from files; VM-side SQLite owned by @duetso/agent (duet memory / duet train); API is a front door through the in-VM gateway. No Convex personal-memory. Train = async job (POST /train → jobId).
  • Agent sessions: full turn protocol (create session / message / SSE events / answer / interrupt; terminal states complete·ask·interrupted·sleep). Convex relays long-running state; SSE is a view, not a lifeline.
  • Folder shares: Syncthing between workspace VMs; read or read-write; recipient picks mount point; smart markdown merge is a later layer on top.
  • Apps: in-VM gateway multiplexes the VM's one public port; URLs service.example.invalid (we don't own duet.app); publish-file → unique URL; custom domains via our edge proxy, not exe's domain feature.
  • Integrations: Composio + model gateway (proxy to Vercel AI Gateway, image/video/audio too, billing passthrough) exposed to external harnesses via API.
  • MCP: hosted remote (service.example.invalid); tools: list/read/write files, memory add/search, share_folder, expose_app, publish_file, run_agent, use_integration, generate_media.
  • CLI: new, named duetfs — bare npm name free (register early), brew clear, zero collisions or model priors, and self-describing so agents can guess semantics (duetfs push). workspace:/path addressing. The duet CLI stays the agent's. (Runners-up checked: dux viable-scoped-only; dx/dia/dfs rejected on collisions/priors.)
  • Onboarding: agent-led self-install (agent visits service.example.invalid, installs, pairs via device-code) or human signup; memory bootstrap by scraping company URL + importing local agent session data. Done-demo: after setup, Claude Code answers business questions and produces on-brand content.
  • Free tier: retire (archive + rm) VMs after 7 days inactivity — poweroff proven useless (auto-restarts). Recreate ≈ 12s on return.
  • Landing page: first page of new apps/web; current LP content + CLI/MCP, agent-friendly framing.
  • Backups: cp-clone snapshots (exe lobby command). Secrets: stored in Convex, injected as VM env.
  • Backend reuse (Example User, 2026-07-06): dig deep into chat-app's Convex backend + schema and reuse aggressively — fully copy where sound, refactor where better. Named targets: credits & transaction ledger (convex/domains/credits · creditTransactions · docs/billing-and-credits.md) and daily/monthly credit-usage reporting (creditDailyUsage · monthlyUsage). All new code written to /write-tests principles (behavior-pinning tests, not implementation details).

Stack & architecture

  • Bun + Turborepo (scaffolded); Convex DB; WorkOS auth; Stripe prepaid credits; Vercel hosting — v1's stack carries over.
  • Edge proxy stays in the Vercel ecosystem (Example User; WS arriving in fluid compute beta). Duration limits are accepted product constraints; keep proxy logic portable in case of exit.
  • In-VM gateway (Hono, v1 pattern) baked into a custom Docker image, runs as a systemd boot service, phones home to register. All in-VM ops over HTTPS; SSH (duet-prod key in Convex secrets) is break-glass only. exe control plane via HTTPS /exec token.
  • API auth: scoped per-user keys (duet_sk_…, ws:{slug}:{capability} grammar) — not v1's overloaded gateway token.
  • @duetso/agent evolves in lockstep; required changes get specified explicitly.

Territory facts (measured / verified 2026-07-05)

  • exe.dev timings (SSH benchmark ×3): create→usable ≈ 12s; restart→usable ≈ 10s; SSH exec overhead ~2.4s; delete ~3.4s. Control plane ~1s per op.
  • No stop primitive: lifecycle is new/restart/rm only; sudo poweroff → auto-restart ~60s later (boot_id proof). Lobby ls reported running while the VM was down → liveness must come from our gateway heartbeats.
  • exe: one public HTTPS port per VM (service.example.invalid, private by default); ports 3000–9999 authed-users-only; no raw TCP ingress, no public IP; /exec is lobby-only (30s, 64KB, no stdin); accounts region-pinned (ours: NYC); pooled CPU/RAM pricing, no free tier; disks grow-only; exeuntu ~4GB; useful extras: cp (clone), stat (metrics), resize, tag. In-VM user exedev, passwordless sudo.
  • v1 blueprints mapped: edge proxy apps/sandbox-gateway/app/[[...path]]/route.ts, in-VM gateway packages/agent-gateway, runner protocol @duetso/agent · duet --rpc · NDJSON, train pipeline convex/domains/train/actions.ts, API-key auth convex/domains/publicApi/auth.ts.
  • This repo: blank slate + working packages/exe-sandbox client (SSH-quoting bug fixed, uncommitted). SSH key ~/.ssh/exe-duet registered on user@example.invalid.

Quadrant 3 · Unknown knownsWhat got extracted

  • The ecosystem thesis (above) — reshaped build order: agent-facing surface first, harness + web app later.
  • First consumer: external devs wiring Claude Code. Reshaped onboarding into a feature: session import — read Claude Code/Codex/OpenClaw local session data to seed first memories.
  • Agent-led self-install: the website must be agent-operable (agent-readable install path, auth completable without a human clicking OAuth).
  • The 60-second demo = definition of done for v1 (install → bootstrap → agent knows the business → on-brand output).
  • Taste: simplest-most-proven-most-maintainable bias (Syncthing pick); stay-in-Vercel bias; path-as-URL grammar; v1 URL scheme kept; short unix-y CLI name; suggestions invited to be overridden when a better way exists.
  • v1 scar tissue: too big a leap (new app + new harness); subsidized competitors → don't build a parallel ecosystem.

Quadrant 4 · Unknown unknownsThe landmine cards

Sweep coverage: exe.dev platform behavior (live experiments + full docs), and the v1 code paths v2 ports — both gateways, e2b client, publicApi auth, custom domains (Codex sweep, claims spot-verified).

LIVE V1 ISSUEUnauthenticated gateway control routes

Evidence: /session/* mutation routes (public config, domains, cron) mount with no auth; only global middleware is cors() agent-gateway/src/app.ts:86,104 — on e2b these are publicly addressable, guarded only by unguessable hostname.

v2 rule: every gateway route authenticates its caller; no capability-URL security. Also: consider patching v1 independently.

DECIDEDEdge WS/SSE limits

Evidence: v1 edge is a plain fetch proxy — no Upgrade tunneling, SSE cut at 300s (maxDuration=400) sandbox-gateway route.ts:6,36,241.

Decision: stay Vercel (WS in fluid-compute beta); explicit upgrade/streaming handling, documented reconnect semantics, portable proxy logic.

SHARP EDGESyncthing × live SQLite

Syncing a hot SQLite file corrupts it. Rule: shares only under a designated drive root; memory DB and .duet/ state live outside any shareable subtree.

SHARP EDGE"Read-only" shares aren't, natively

Syncthing receive-only still accepts local writes (reverts later). Rule: enforce read-only via FS permissions on receivers; Syncthing mode is transport, not guarantee. Example User: acceptable if this proves brittle — not a deal-breaker.

OPEN — SPIKE #1VM-to-VM sync connectivity

exe VMs cannot listen publicly (no public IP, no raw TCP ingress) — sync is direct only if exe's internal VM-to-VM network allows peer dialing; else we run our own Syncthing relay (works, adds infra). Two-VM spike decides.

SHARP EDGEPooled CPU/RAM → noisy neighbors & abuse are ours

We buy the pool; a miner burns everyone's capacity; free public URLs attract phishing. Rule: per-VM caps at create, cgroup caps in-VM (v1's runner-cpu-cap pattern — easier on a full VM), stat metering, abuse policy before free tier opens.

SHARP EDGELong-lived fleet needs upgrades day one

e2b rebuilt the template per sandbox; exe VMs live months. Gateway self-update (or backend-pushed), versioned components in API responses, memory-schema migrations owned by @duetso/agent.

DECIDEDAgents delete drives

Disk = only truth; agent rm -rf is a when. Decision: cp-clone snapshots. Confirm cp semantics on a running VM (crash-consistency) before relying on it.

SHARP EDGESession import is a secrets minefield

Transcripts contain pasted keys; formats drift. Rules: opt-in per source; secret-scrub before write; land as source: import, bulk-reviewable/deletable; parsers quarantined best-effort. Secrets generally: Convex-stored, env-injected — never in memories/files.

SHARP EDGESelf-install auth = prompt-injection surface

Device-code pairing with a non-bypassable human approval step; research adjacent best practices (RFC 8628 device flow, MCP OAuth, GitHub CLI pattern) at spec time.

DECIDEDSlug grammar & domains

App URLs on service.example.invalid (duet.app not owned). Port v1's existing slug protections; reserve www/api/mcp/…; single-hyphen slugs so -- stays unambiguous.

DECIDED / RULESPorting-assumption cards (Codex sweep)

One public gateway URL + private internal ports (v1 bakes e2b per-port URLs into backend/resolve/viewers e2b client.ts:105 · sandboxes/actions.ts:413) · no wake-on-request lifecycle; heartbeat liveness (client.ts:404 · route.ts:38) · gateway builds its own streaming Range/206 download endpoint (envd gone; v1 buffered whole files, no Range public-app-service.ts:397 · files/[storageId]/route.ts:16) · one token story enforced uniformly (v1: 24h file expiry vs eternal DB token credentials.ts:70 · publicApi/auth.ts:31) · systemd boot service replaces nohup watchdog (setup.ts:237,269) · image contract explicit (user exedev, paths — v1 hard-codes /home/synthetic-user/code>) · don't port v1's half-built provider abstraction; greenfield interface.
