**Grounding**

Read: `specs/agent-drive/map.html`, `specs/agent-drive/interview-delta.md`, repo `README.md`, v1 `chat-app` gateway/backend paths, current `packages/exe-sandbox`, and `duet-agent` CLI sources. Inference: I choose `apps/api` as a Hono REST host on Vercel, matching the map’s J2 recommendation, with Convex kept as database/state/crons.

Deviations from nominal map order: slice 0 absorbs exe-client freeze plus all test/platform probes because the map/delta require environment before features; Convex Auth lands before workspace provisioning because workspace ownership depends on real session identity; apps and publishing are split because the delta makes apps backend anchors while published files/folders have a different slug/access model; billing lands before final launch/demo hardening, not as an afterthought.

## 4. Risks and Scope Firewalls

Global firewalls:

- No WorkOS, no migration from `chat-app`, no raw TCP between VMs, no capability URL security.
- No file manifests for apps; `public.config.json` is v1-only.
- No syncing `.duet/`, memory DB, secrets, or gateway state.
- No wake-on-request assumptions; exe VMs are always-on until archived/removed.
- No per-app spend caps; workspace cap only.

Slice firewalls:

- 0 must not implement product API behavior beyond probes.
- 1 must not port chat/org/channel concepts wholesale; only auth/user/workspace primitives.
- 2 must not use SSH for normal production operations; SSH stays break-glass.
- 3 must not reuse v1 `duet_gt_` gateway-token auth except as a cautionary source.
- 4 must not expose unauthenticated gateway routes, including `/health` detail beyond public liveness.
- 5 must not add web-only workflows; CLI must work from a fresh container.
- 6 must not store Convex personal memory; VM SQLite remains owner.
- 8 must not allow nested share mounts or Syncthing of hot SQLite.
- 10 must not start recipient copies of apps; origin VM is canonical and origin pays.
- 11 must not redirect old publish slugs after edits.
- 13 must not invent a second ledger; port and rescope the v1 ledger.
- 14 must not move business rules into React components.

Highest risks: exe custom-image mechanics, WS duration/idle limits on Vercel fluid compute, Syncthing over tunnel reliability, read-only share enforcement by FS perms, public URL abuse, agent transcript secret leakage, and ledger/reservation correctness under retries.
