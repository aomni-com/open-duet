# Preserving background services during adoption

A runner cgroup can outlive its agent. Its non-RPC services remain workspace work after the gateway owner exits, and adopting a new runtime must preserve them. The temporary adoption census distinguishes these services through present ownership, ancestry, cgroup identity and file dependencies. Accepted agent commands, due wakes, Train jobs, backup capture, RPC runners, live owners and uncertain relevant processes still defer the cut.

The census checks observed executable, cwd, arguments, direct environment paths, mappings and descriptors against the retiring installation, including symlink targets and standard path-list variable components. A legacy CLI PATH entry can fall through to the stable `/usr/local/bin` alias; a custom direct reference cannot. Marker-free children inherit the conclusively orphaned leader's classification, including children in another cgroup. New children with an inherited dead-owner marker qualify through their preserved parent. PID/start/parent/cgroup identities and owner absence are rechecked. An unrelated service using an option named `--rpc` remains outside Duet runner ownership. Effective systemd commands must select the isolated Bun executable as well as the expected arguments.

These checks describe present dependencies. They do not freeze background services or constrain their future instructions. The private old recovery installation remains until the strict runtime pairs settle. Requiring arbitrary workspace services to stop would violate the user's preservation requirement and exceed the ordinary updater's contract.

[The receipt](receipt.json) binds the separately built helper, frozen target and cached OS inputs. Compressed observations and historical producers record a disposable private-cgroup Docker systemd transition: the same orphan leader and marker-free child remain running, native memory survives, the target certifies and the kernel boot ID is unchanged. This is not provider or control-plane evidence. The Syncthing sentinel records process continuity, not protocol acceptance. Later guard tightening is covered by falsified regression tests and a real read-only census of the unchanged pair, rather than a repeated transition.

The first independent review's proposal to freeze unrelated services was rejected for the contract above. Its direct-environment finding was fixed; follow-up relative/symlink and descendant findings were reproduced and fixed. The final review also corrected standard path-list aliases, inherited-owner descendants and unrelated RPC option spelling. All original application/runtime bytes remain unchanged. The operational producers here are compressed historical references, not a new shipping installer or recurring service.
