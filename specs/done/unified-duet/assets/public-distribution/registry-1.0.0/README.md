# Public registry release 1.0.0

[Distribution verification](distribution-verification.json) binds three cold
registry installs to the public tarball and the exact original main source.
Linux x64, Mac ARM64 and Mac x64 under Rosetta passed native memory/vector/RPC,
composed login/files, OAuth-patch and terminal UI probes. Mac proofs use real
architecture-specific Syncthing binaries with private fixture homes; HTTP and
launchctl edges are modeled. Rosetta is not a physical Intel Mac.

The original publication workflow failed during its immediate post-publish
registry read and retained no receipt. It remains failed. The separately
[recovered verification](original-recovery/recovered-verification.json) records
a rebuild of that exact source using the original Bun, Node and npm versions,
whose full tarball equals the public tarball byte for byte. Registry timestamp
and workflow-completion time differ; that discrepancy remains unresolved.
No signed source-provenance assertion is inferred from reproducibility.

Each platform's installed-closure receipt matches tarball integrity, complete
packed entry bytes and actual optional native dependencies. The first fixture
install attempts failed before config resolution because user/global npmrc paths
were identical; corrected distinct empty files produced the cold installs.
The capture owner's prefix-path regression is retained with its four passing
validation cases. Probes and captures leave no customer processes or credentials.

Original inputs remain immutable: the source archive is reproducible from its
Git revision and checksum, and official tool archives from retained distribution
URLs and checksums. Those large archives and duplicate bundled entries stay out
of this repository. The registry tarball is retained once. Compressed logs and
scratch producers are historical evidence, not another release mechanism;
stored-evidence manifests bind their exact decompressed bytes.

The user waived npm deprecation of the historical duetfs versions. The first
attempt remains preserved as a failed npm HTTP403 operation; no deprecation is
claimed. The [publishing-owner retirement](legacy-retirement/owner-retirement.json)
records the old Release and temporary retirement workflows disabled, the
one-shot branch removed and only the old repository's NPM_TOKEN copy deleted.
The new repository's publishing credential remains present. Historical duetfs
packages stay on npm; neither this repository nor managed VMs consume them.
