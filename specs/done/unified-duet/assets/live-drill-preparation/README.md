# Disposable provider drill preparation evidence

These frozen inputs and receipts record preparation of physical fault-injection
proof. Provider fixtures use controlled loopback API/model edges and their own
identities; they do not create backend workspaces or establish real control-plane
acceptance. The [evidence validator](../../../../../packages/test-harness/src/staging-e2e-synthetic)
owns the retained receipt contract.

[Interrupted adoption](../provider-drills/interrupted-adoption/receipt.json)
observes real legacy-image services and distinguishes image content from the
seeded historical gateway. [Strict runtime drills](../provider-drills/strict-runtime-r4/receipt.json)
observe native CLI-only activation, repair, matched rollback and live-work
refusal. Exact fixture deletion belongs to each provider receipt; the
[dedicated journey](../staging-journeys/unified-duet-final/receipt.json) supplies
real staging control-plane acceptance separately.

The one-time producer source belongs to its recorded Git revision. Frozen
metadata, patches and failure receipts remain evidence; compressed reference
probes preserve their original source bytes without a live import into retired
producers. They do not own installation or a continuing VM update rail.

The shipping runtime manager remains the sole installer and recovery owner.
Fixture setup must respect its release-directory owner, complete inventory,
physical cohort and first skills-install prerequisite; a prepared packet or
metadata-only unit check cannot substitute for those native observations.
