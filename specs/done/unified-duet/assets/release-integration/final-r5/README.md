# Final ordinary runtime verification

The [production receipt](production/verification.json) verifies all fourteen
attachments on the final R5 runtime with complete, historically certified R4
rollback inventories. All original OS boot identities and thirty-one independent
process identities survived. After gateway transitions, all seventy-eight
unchanged app configurations passed fresh supervisor readiness and TCP checks.
This proves process readiness and socket reachability, not application business
flows. Concurrent SSH observation failures remain preserved beside successful
serial retries; app reconciliation was not repeated.

Both existing staging VMs passed complete current/previous physical inspections
in [staging](staging/physical/stored-evidence.json). Hosted immutable and canonical
API streams matched all eight artifacts in both environments. R5 changes only
the command compared with R4; the verified OS image remains its provisioning
owner and supplies R4 as a seed before ordinary updates.

The [production app snapshot](main-apps-final.json) records all seven apps ready
on the original main publication revision. Later publisher-only and evidence
commits retain command source, but independent compilation can change executable
bytes and runtime identity. The [constructor proof](../../runtime-constructor/README.md)
records that boundary. The original promotion and publisher-fix
transcripts are retained separately.

The actual image/native probe and three public registry platform probes pin
maintained command behavior. Generic historical probe output mentions sidecar
failure cases that these environment-prefixed invocations did not execute;
these receipts certify only their recorded results. Earlier matching runtime
drills retain the repair and rollback proof for unchanged native assets.

Transcripts and scratch producers are frozen gzip evidence, not maintained
operator tools. Each stored-evidence manifest binds decompressed original bytes
and stored bytes. Original absolute paths identify where an observation occurred;
new operators use the maintained runtime and app owners.
