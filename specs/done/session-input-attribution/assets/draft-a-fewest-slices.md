# Draft A — Fewest Slices

Bias: force the schema change through the smallest number of coherent, always-green checkpoints.

The draft proposed four slices:

1. Atomically replace origin/submitted time and misleading user-only event names across contract, API derivation, Convex persistence, history, idempotency, browser projection, and optimism.
2. Resolve current identity and replace the plaintext delivery composer with one escaped backend renderer.
3. Turn the typed sender into actual-author transcript presentation and prove it in the existing authored-message playground.
4. Cut over teaching/docs and extend the existing selectable sessions-and-jobs staging journey.

Useful pressure retained in synthesis:

- A required sender cannot land contract-only without creating an optional/dual shape somewhere else.
- Updating browser projection in the atomic cutover prevents a compile-only compatibility adapter.
- The model renderer and visual presentation are independently testable consumers of the same durable sender and need not block one another.
- Existing playground and staging owners are sufficient; new harnesses would be sediment.

Rejected during synthesis:

- Combining the model renderer into the atomic data slice would make the first review too broad and erase a valuable byte-exact checkpoint.
- Combining visual presentation with docs/staging would mix subjective UI iteration with public-contract closeout.
