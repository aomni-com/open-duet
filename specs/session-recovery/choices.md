# Recovery choices

## Stop and status repair

- **When:** gateway/backend recovery pass. **Decision:** stopping an absent runner cancels its saved commands and wake, but keeps its private checkpoint for an explicit continuation. The gateway records a separate stop cursor and reports that no native runner received the interrupt, so the API can also cancel input still queued upstream. **Gap:** the audit did not prescribe the stop protocol. **Rationale:** launching a model merely to stop it creates work and fails when the agent folder is unavailable. **Consequence:** pausing or stopping never automatically resumes that work later; a new user input is required.
- **When:** checkpoint reconciliation and terminal-coverage passes. **Decision:** repair a stale running label only when an interrupted local checkpoint has no live runner, pending command, wake, or undelivered event, and the backend input cursor and event sequence still match. Pending backend input and archived sessions remain untouched. **Gap:** historical checkpoints have no independent input-generation field. **Rationale:** comparing only the input cursor misses newer timer turns; replaying an old terminal can overwrite newer work. **Consequence:** ambiguous records remain inconclusive instead of being automatically restarted or declared complete. Observation retries survive pause and back off when the API is unavailable. The repaired terminal records which input it covers, so API callers waiting for that input also finish.
- **When:** interrupted grouping pass. **Decision:** an interrupted turn is inactive even when its relay definition has no final outcome. Repair existing indexed list rows with the repository's bounded migration framework. **Gap:** an unfinished relay can mean either paused work or ongoing work. **Rationale:** interruption is evidence of inactivity; a state named “done” or an assistant's completion claim is not. **Consequence:** complete-but-unfinished machines retain their existing grouping until stronger execution evidence exists. Migration invocation belongs to rollout, without restarting sessions.
- **When:** journal restart-ordering pass. **Decision:** persist a monotonic journal position in each private snapshot and apply only later records on restart. Reuse input/revision evidence to read legacy records; if an old autonomous wake cannot be ordered safely, retain it under a recovery-blocked marker until explicit newer input or stop. **Gap:** a terminal waiting for upload could already be reflected in the snapshot and would erase newer work when replayed. **Rationale:** input cursors cannot order timer turns, and an event-ID lookup becomes ambiguous if that record is corrupt. **Consequence:** private journal/snapshot metadata grows by small ordering fields; no server table changes. Ambiguous legacy work is never silently replayed, while explicit input remains an escape path.

## Agent progress

- **When:** transition suspension pass. **Decision:** after the existing bounded next-state retries are exhausted, ask for continuation and save the outstanding state name. Reuse the completed state's output from existing history when the user continues. **Gap:** the failure previously ended the relay without a useful recovery path. **Rationale:** repeating the finished worker could duplicate external changes; unlimited parent retries could burn tokens without progress. **Consequence:** recovery retries the parent's decision, while deliberate state selection can still rerun work. Historical failed or cancelled relays are not revived automatically.
- **When:** control-boundary pass. **Decision:** commit a parent's accepted control before processing queued user input; keep queued input under the turn runner's durable ownership until consumed. **Gap:** a follow-up could extend the underlying model loop past a control boundary. **Rationale:** resetting the duplicate-control guard alone would allow an unexecuted decision to be overwritten. **Consequence:** sequential user turns remain valid and their messages survive a suspended turn. Editing follow-ups replaces their saved delivery copies, while retained steering input stays independent; multiple controls in one actual parent pass remain invalid.
- **When:** provider compaction pass. **Decision:** retain a final tool call and its result together even when the pair exceeds the soft compaction budget. **Gap:** trimming previously allowed the result to survive alone. **Rationale:** an orphan result is an invalid provider request; a soft budget cannot justify breaking the wire protocol. **Consequence:** a single large interaction can exceed that budget. This fixes a reproduced mechanism, not every historical provider error whose original request was unavailable.
- **When:** sleeping-relay edit pass. **Decision:** add a non-control tool that edits an existing future state's instructions/configuration while preserving current progress and the scheduled wake. Editing a running or scheduled state still requires explicit selection with an override. **Gap:** the existing tools selected/executed or replaced the whole machine. **Rationale:** changing future instructions should neither execute external work now nor reset relay history. **Consequence:** the new tool adds no scheduler or persistent schema; live execution changes remain explicit.
